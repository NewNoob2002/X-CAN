# USB/CAN v2 本地验证

日期：2026-09-14。结论：本次协议编解码与主机会话关联的本地测试通过；没有USB/FDCAN驱动集成、烧录或CAN流量。

## 交付

- [v2规范](../../../USB_CAN_PROTOCOL_V2.md)：24字节头、最大512字节消息、变长CAN记录与批次、会话/事务/事件序号、控制响应与TX完成、背压/丢失统计和恢复边界。
- firmware/src/protocol_v2.h/.c：无堆分配C实现，严格消息与CAN字段校验，流式拆包、剩余字节消耗和错误锁定。
- host/src/protocol_v2.rs：Rust编解码、ClientSession单请求关联、事件缺口/回绕、单次TX完成关联；由host/src/lib.rs导出。
- tests/protocol_v2_vectors.txt：106组固定共享线格式样例，由独立Python struct布局生成。C与Rust均解码并逐字节重编码这些相同向量。
- tests/protocol_v2_test.c及host/tests/protocol_v2.rs：可重复本地测试。命令和源码SHA256见result.json。

| 检查 | 结果 | 范围 |
|---|---|---|
| C v2，ASan/UBSan | 通过 | 106组合法/非法消息，DLC全部16档、Classic/RTR、标准/扩展ID、FD/BRS/ESI、5帧满长FD及最大512字节消息 |
| C/Rust共享向量 | 通过 | 逐字节一致；每条向量从1到整条长度的所有分块大小、两条消息粘包、截断与失败锁定 |

| Rust v2 | 9项通过 | 2项模块测试、7项集成测试；包括混合长度交互脚本、事件穿插、序号回绕/歧义、ID耗尽、旧会话/错响应/超时、TX接受与完成关联 |
| 原v1回归 | 通过 | C协议测试仍通过ASan/UBSan；Rust原有1项测试通过 |
| Clippy all-targets | 通过 | -D warnings，无新增依赖 |

人工审查范围：长度先于索引/拷贝检查、DLC查表边界、批次计数与剩余长度、编码容量、整数位移与小端处理、解析器失败后停止、响应/事件/TX关联。不存在直接映射packed结构或未对齐整数指针访问；每个解析器由单一所有者调用。C入口要求有效、非重叠的调用者缓冲区；输出仅在返回成功时使用。Rust会话层不处理实际USB超时计时，I/O层在错误/超时时必须调用invalidate。

Clippy初次检查指出测试辅助函数的分块写法与可用数组替代的Vec；已修正并重跑通过，不掩盖测试失败。随后对TX关联补充了提前/错误完成拒绝及BUSY后释放本地待发状态的回归。

## 尚未实现与不可推断项

板上固件和现有CLI仍为v1；v2 C文件未加入固件CMake源列表。未来需实现EP0版本发现、设备会话令牌与请求去重、控制/事件调度、FDCAN配置与帧队列、位时序校验、硬件丢失归集、时间戳来源及USB消息结束/ZLP行为。

交互脚本是纯内存消息测试，没有模拟驱动能力或宣称物理发送成功。ClientSession不实施完整CAN状态机，不校验stream生命周期和frame_sequence语义；这些需要CAN业务层及后续台架测试。Windows实机、主机停读的真实背压、断连清理、控制响应延迟、ISR负载、内存峰值与吞吐不在本次通过范围内。

本轮将计划更新为“M2协议基础已完成，CAN驱动与USB接入待实现”；不将M1待关闭项或M2整体标为完成。
