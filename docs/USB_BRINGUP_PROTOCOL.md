# Vendor USB bringup协议v1

本文件仍对应当前上板固件。支持完整CAN-FD帧的后续协议见 [v2规范](USB_CAN_PROTOCOL_V2.md)，已完成独立编解码与本地测试，尚未接入USB/FDCAN。

仅用于M1设备信息与回环。VID=0xC0CA、PID=0x0313；用户原文COCA按第二位数字0处理并告知。接口class=0xFF，Bulk最大包64字节；上位机从描述符查找端点。串口独立，不使用CDC。

每个请求/响应固定64字节，小端，只允许一个在途事务。OUT可拆成短片段，累计64字节后处理；IN返回64字节。有效载荷长度不改变记录总长，尾部填零。主机停读时OUT通过NAK施加背压，不无界排队。

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 4 | ASCII XCAN |
| 4 | 1 | 版本1 |
| 5 | 1 | 操作码 |
| 6 | 1 | 请求必须0；响应0成功、1头/版本/长度错误、2操作码/参数不支持 |
| 7 | 1 | payload长度0..52 |
| 8 | 4 | 事务ID，原样回显 |
| 12 | 52 | payload；响应未用字节清零 |

- 0x01 INFO：请求长度0；响应14字节：clock_hz u32、DBGMCU_IDCODE u32、uptime_ms u32（约49.7天回绕）、termination_declared u8（0/1，0xFF尚未稳定）、safe u8（本版恒1）。safe表示逻辑模式，不是电气反馈。
- 0x02 ECHO：原样返回0..52字节任意二进制。
- 没有CAN、注入、复位、Flash或选项字节写入命令。

分片超过记录剩余空间会清除未完成记录并返回错误；不承诺从垃圾字节流自动恢复边界，不允许流水线请求。主机遇到超时/短写/错误后停止会话；若遗留不完整请求，重新配置USB或拔插后再开始。配置disable清空接收状态，epoch拒绝旧配置回调；排队/传输失败需重新配置。此限制适用于当前单事务回环，后续CAN帧流另行设计吞吐与拥塞策略。

序列号由UID生成。MS OS 2.0描述符声明WINUSB，GUID为{D9E71DA8-3CB5-4E3B-8A53-5843414E0001}。未启用remote wakeup；Windows绑定及挂起/恢复待实测。

C解析器检查载荷边界、非法版本/操作码和info布局；Rust检查长度和事务ID。Linux实机106次整包/7字节拆分回环及越界长度拒绝已通过，不等同于持续吞吐或异常拔插验收。
